# PDF 双语左右对照翻译

## 工作约定

译文由当前会话模型生成，不调用外部机器翻译服务。根据文档识别原文语言、领域和页面类型。电子技术资料是常见场景，不是适用范围限制。遵循用户的明确选择。

所有文本文件使用 UTF-8 无 BOM。使用技能时只读取英文 SKILL.md，不读取中文 README.md。修改任一技能文档时，同步更新另一语言的对应文档。

任务文件放在本技能仓库之外。访问脚本前解析实际安装目录。保留 CC Switch 链接入口，并在解析后的本体中维护；不自行迁移技能。

建议的任务目录如下，路径仅作示例，不固定到某台电脑：

~~~
work/bilingual/<document>/
  state.json         # 可恢复的文本、映射、术语、布局与验收记录
  baseline.json      # 原文预检
  audit.json         # 最终程序审计
  build.py           # 针对本次任务的确定性排版脚本
  renders/           # 整页、原页与差异图片；可清理
outputs/
  <stem>_双语对照翻译.pdf
  <stem>_recovery/    # 状态、生成脚本及必要元数据；不保留重复渲染缓存
~~~

保留原文件名。恢复包内部尽量使用相对路径，记录外部原文件位置及 SHA-256。记录字体名称、指纹、允许的获取来源、依赖和生成参数，确保可以重新生成。未经许可不分发字体文件。

## 交付要求

1. 完整、准确、原文保真与可读性是交付条件，其次优化位置对应，再考虑字号一致和装饰。不得通过省略限定条件、合并不同内容或过度缩小文字来塞入版面。
2. 每个原页对应一个双语输出页，左侧以原比例保留原始可见区域。中文区默认与原页同宽、同高。保留主要区域和分栏，以语义块对齐，不追求逐行一致。
3. 结合章节及跨页上下文翻译标题、段落、列表项、表格单元格、公式说明、图注及相关图中标签。保留数字、单位、型号、变量、上下标、公式编号、条件及否定。无法确认时保留原文措辞并记录疑点，不无提示猜译。
4. 图形留在左侧。右侧对应位置安排图号、中文图注及必要的标签、图例和坐标轴说明，以图号、原文标签或位置消除歧义。保留有助定位的空白，不放空色框、虚构图形或把图注全部堆到页顶。
5. 保留真实的表格行列、表头、数值及脚注关系，不将表格压成竖线分隔的段落。原文重复的公式也应重复呈现。仅含数字、标识符或符号的内容可原样保留，并记录理由。
6. 中文溢出时先调整换行、列宽及块内间距，再利用邻近空白局部重排，必要时适度拓宽中文区。原文区保持不变。仍不能兼顾完整、可读及同页对应时，指出具体页面和未解决约束，不宣称完成。
7. 保留原图片编码与质量，中文使用真实可搜索、可复制的文字及轻量矢量线条。字体在全书共享，按最终字形集合子集化，修订后清理废弃资源。额外备用字体必须有明确的缺字补充用途。
8. 修订从原 PDF 和恢复数据重新生成，不在旧双语文件上反复叠加。

设计页面样式或处理密集页面时，按需读取 [layout.md](references/layout.zh-CN.md)。进行 PDF 合成、资源处理和结构验收前，读取 [pdf-integrity.md](references/pdf-integrity.zh-CN.md)。

## 辅助工具

要求 Python 3.10+。在已有合适环境或独立环境安装 requirements.txt，不把当前电脑的运行时绝对路径写入任务脚本。

~~~
python -m venv work/pdf-skill-env
<venv-python> -m pip install -r "<skill-dir>/requirements.txt"
<venv-python> "<skill-dir>/scripts/pdf_tools.py" --help
~~~

工具负责检查与渲染，不翻译、不自动排版、不优化 PDF，也不证明语义准确。

| 命令 | 输入 | 输出与用途 |
| --- | --- | --- |
| inspect SOURCE --out baseline.json | 原 PDF | 页尺寸、旋转/裁切、提取提示、链接书签，以及唯一可达资源基线。 |
| audit SOURCE FINAL --state state.json --out audit.json | 原文、最终 PDF；可选状态文件 | 原文区图像/文字比较、图片语义指纹、链接书签检查、资源增量及体积变化。 |
| render FINAL --source SOURCE --state state.json --pages all --out renders | PDF；可选原文及映射 | 逐页 PNG 和 index.json；提供原文时另生成原页和差异图片。 |
| check-state state.json --final --out state-check.json | 恢复 JSON 及其引用文件 | 缺少译文或映射、指纹变化、失效记录和最终检查覆盖缺项。工作中省略 --final。 |

含空格的路径应加引号。报告及渲染文件仅在明确指定 --overwrite 时覆盖，输入 PDF 不会被编辑。--pages 支持 all 或从 1 开始的选页，例如 1,3-5。审计与渲染默认为 144 DPI、每页 4000 万像素上限、RGB 差值容差 16、变化像素比例 0.001。这些是比较参数，不是翻译质量门槛。细节检查使用 --dpi，仅在内存允许时明确调整 --max-pixels。放宽比较容差时记录原因并检查差异，不以提高阈值掩盖错误。

退出码：0 表示程序检查完成且没有错误，仍可能有警告；2 表示审计或状态检查发现错误；1 表示运行失败。渲染成功仍明确保留 visual_review_completed 为 false。

创建恢复数据时读取 [state-and-qc.md](references/state-and-qc.zh-CN.md)，其中定义格式、坐标、验收生命周期和最小示例。原文块清单本身也必须视觉核查；工具无法发现同时遗漏于清单和译文的内容。

## 工作流程

1. 预检原文，保存指纹及资源基线。根据实际内容渲染代表性的正文、密集表格、多图、公式、横向及旋转/裁切页。对照可见原文检查提取结果，确有需要时使用本地 OCR，并核查数字与符号。为本书选择字体、正文/图注字号、页眉安全区及克制的配色。
2. 为每页建立语义块清单，分配稳定 ID 和原文边界框。保存原文、有关跨页上下文、表格结构、图形锚点及翻译状态。从定义及实际上下文建立术语表，厂商命名规则仅在相关厂商文档启用。
3. 按章节或上下文组翻译，再排版代表性的难页。检查样页是否完整、表格是否真实保留结构、图注是否对应、字号是否可读。解决设计问题后再扩展到全书，每批保存译文和布局参数。
4. 用任务专用脚本从原文构建。在规范化或明确处理旋转和裁切后，优先扩展原页可见区域并添加右侧文字，保留交互对象及其目标。工作中运行 check-state，使用 render 检查单页并修复版式问题。
5. 完成全部保存、字体子集化和资源清理。冻结最终文件，清除旧验收记录，计算指纹并对照原文运行 audit。解释每项警告，调查新增图片、字体或无法解释的体积增长。不能单凭增长百分比决定是否通过。
6. 对该最终版本分别完成三类验收：（a）逐块检查翻译覆盖、准确性、术语、条件、否定、数值、单位、表格和公式；（b）打开最终文件的每一页，放大密集表格和细小图注；（c）原文区保真、原图片、字体与资源增量、链接书签可用性，以及中文可搜索、可复制。联系表仅供导航，不能替代整页检查。程序通过及渲染完成不能代替这三类验收。
7. 记录实际检查的页码、检查者和时间，原文/输出/内容指纹、审计路径及警告处理结果，运行 check-state --final。发生任何变化后按需重新生成，重做受影响的语义检查及最终文件全页视觉和结构检查，不沿用失效验收。
8. 交付 PDF 和恢复数据，说明页数、原文/输出大小、绝对与相对增长、资源增量、验证范围及保留疑点。如实说明限制，不将未查看页面或未解决翻译宣称为完整通过。

明确要求维护本技能时，遵循 AGENTS.md 和 [maintenance.md](references/maintenance.zh-CN.md)。普通翻译任务不得进入技能仓库。
