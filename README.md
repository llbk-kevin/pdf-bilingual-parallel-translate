# PDF 双语左右对照翻译

## 安装

首次安装时，将仓库克隆到工具支持的技能目录，目录名为 pdf-bilingual-parallel-translate；在 Python 3.10+ 环境安装 requirements.txt，并用该环境运行 scripts/pipeline.py。prepare 时指定本机可用中文字体，仓库不附带字体；输出保存在技能目录之外。已有 CC Switch 安装必须保留托管链接，更新解析后的本体，不替换入口。命令与输入要求见 [中文操作说明](references/practical.zh-CN.md)。模型负责翻译与逐页查看，脚本负责构建与检查。

## 工作约定

使用当前会话模型，不调用外部机器翻译。根据当前文档确认语言、领域和读者。保留原文及已有译本。文本采用 UTF-8 无 BOM。普通使用读取英文主入口及 practical.md，其他英文参考仅按具体问题读取。维护遵守 AGENTS.md，同步中文文档，保留解析后的 CC Switch 链接。

默认 **practical 阅读模式**：原文完整、请求页面齐全、中文正常、主要图文可读、PDF 可独立打开。零星措辞、断行、小残影及美观差异记录后交付，不全面校订术语。公式、数值、型号和引脚名直接复用，不依据乱码猜测。已知且可安全修正的错误随当前批次处理。

仅明确要求精细验收时用 **strict**。状态须记录所选模式。均不设置固定时间、token 或轮次上限。为阻断问题及有证据的流程缺陷继续迭代，不因新增美观建议返工。

## 成品要求

每个选定的原文可见 W × H 页面生成 2W × H 对照页。左侧原比例保留，右侧复用图片、曲线、表格与背景，局部替换中文。按稳定 ID 翻译完整段落，不逐行割裂语义或使用其他提取器序号。原文字形事实不可改。扫描或转曲标签用有记录的中文浮层框：位置能明确对应原文即可；practical 不要求精确擦字、恢复背景或匹配原色，露底、英文残字及轻微错位不影响阅读时直接保留，不为这些单独重建。通过 source_render_index 换算像素而非猜倍率；对照原图检查覆盖区，保证表格数值和图纸线条可读。

在原段落、单元格或标签内排字，必要时适度调字号及使用已核实邻接空白。不移动图表框架，不截断含义，不猜测数学字符，不静默切换纯文本右栏。无法解决的阻断问题保留草稿并明确受影响部分。

## 文件存放

原文 PDF、已验收双语 PDF 和以完整原文 stem 命名的工作文件夹并列存放：

~~~text
文档所在目录/
|-- <原文stem>.pdf
|-- <原文stem>_双语左右对照翻译.pdf
`-- <原文stem>/
    |-- 交付说明.md
    |-- recovery/
    `-- work/
        |-- 候选、状态、审核和日志
        `-- rebuild/
            `-- 按需重建的 PDF 及其配套 JSON
~~~

仅将已验收 PDF 发布到工作文件夹外，说明和全部中间文件留在工作文件夹内。普通交付核对恢复依赖；只有需要恢复、维护验证或用户要求时才执行 recovery_argv。交付时按此结构核对本任务新建文件的去向，无需整理预先存在的无关文件。

## 默认流程

1. **预检。** 查找具备 requirements.txt 依赖的 Python 3.10+ 和中文字体。pipeline prepare 接收原文、源页和字体，冻结恢复脚本、生成清单，先处理兼容阻断项。查看原页段落、扫描字和公式边界。仅命名需要时读 naming.md；重命名原文须明确批准。
2. **翻译与映射。** 读取简洁 inventory，pipeline apply 批量写入译文，merge_ids 合并完整段落。公式和标识附理由保留，仅对必要扫描文字加局部覆盖；相邻数值、尺寸和表格单元格视为保护区，以可辨认尺度对照前后具体数值。逐条修链接使用 link_overrides_patch。实际查看后确认页清单，每批保存 authoring state，不手改 qc。 长文档按连续源页或章节分包，由单一协调者依序合入。恢复时用冻结入口的 `status` 读取磁盘进度。按原页核实预置保留块，只有处理决定变化才写编辑。
3. **构建。** 用冻结的 pipeline build。调整只选受影响页，同类溢出集中修复；就绪后构建完整请求范围。始终从原文及状态生成，复用指纹匹配候选。局部修正使用 apply 返回的 preview_argv；后续构建省略 --source。失败时捕获退出码、stdout、stderr，读取 last-error.json，不为获取诊断原样重跑。 遇到 preserved_glyph_removed，先处理相邻替换并预览该页，核对完整公式或标识。
4. **集中检查与修复。** verify 对生成状态一次渲染，同时服务审计和查看。以适当阅读尺度实际看每个需检查页，有疑问才放大，通过 review 登记观察；按 `inventory_review_needed` 补做原文清点，并与实际查看一同登记。同一候选可复用原审计和渲染。原文损坏、缺页、大段漏译、乱码及主要图形遮挡需修复或明确披露受影响部分。优先处理流程缺陷，无害差异附理由保留，不改掩码追求零差异。编辑后 verify --previous-state 保留未变化页的原始证据，仅真实共享依赖或上下文变化时扩大复查。 有待修页时，先登记已实际查看且无阻断的页面，另报待修项；verify --previous-state 可复用这批局部审核。
5. **交付。** publish 检查冻结输入和证据，按相同字节发布，自动生成资源、哈希及恢复说明。普通任务做恢复一致性冒烟；独立重建和资源稳定性实验留在维护或构建资源逻辑改变时。如实报告模式、页范围、保留问题和路径；样本不可称整本译本。

## 命令与产物

完整接口见 [中文操作说明](references/practical.zh-CN.md)。每份文档在同名工作文件夹内保存 recovery/ 和 work/，仅向外层发布验收 PDF。用户 PDF、字体及测试产物不进技能仓库。不要自动删除恢复目录，否则丢失编辑和审核证据。

低层 inplace.py、pdf_tools.py 继续支持，严格/手工细节见 inplace、state-and-qc、building 的配对参考。verify 已生成匹配证据时不重复 audit 与 render。状态统一使用 v3。

保留原始 144 DPI 测量（RGB 容差 16、变化比例 0.001）。阅读模式允许保留已查看右侧差异，原文损坏、字体失败、范围错误仍阻断。
