# PDF 双语左右对照翻译

## 工作约定

使用当前会话模型，不调用外部机器翻译。根据当前文档确认语言、领域和读者。保留原文及已有译本。文本采用 UTF-8 无 BOM。普通使用读取英文主入口及 practical.md，其他英文参考仅按具体问题读取。维护遵守 AGENTS.md，同步中文文档，保留解析后的 CC Switch 链接。

默认 **practical 阅读模式**：原文完整、请求页面齐全、中文正常、主要图文可读、PDF 可独立打开。零星措辞、断行、小残影及美观差异记录后交付，不全面校订术语。公式、数值、型号和引脚名直接复用，不依据乱码猜测。已知且可安全修正的错误随当前批次处理。

仅明确要求精细验收时用 **strict**。旧状态缺少模式字段仍按严格语义，不改写历史验收。均不设置固定时间、token 或轮次上限。为阻断问题及有证据的流程缺陷继续迭代，不因新增美观建议返工。

## 成品要求

每个选定的原文可见 W × H 页面生成 2W × H 对照页。左侧原比例保留，右侧复用图片、曲线、表格与背景，局部替换中文。按稳定 ID 翻译完整段落，不逐行割裂语义或使用其他提取器序号。原文字形事实不可改。扫描或转曲标签用有记录的小白底框，通过 source_render_index 换算像素而非猜倍率；对照原图检查覆盖区，保证表格数值和图纸线条可读。

在原段落、单元格或标签内排字，必要时适度调字号及使用已核实邻接空白。不移动图表框架，不截断含义，不猜测数学字符，不静默切换纯文本右栏。无法解决的阻断问题保留草稿并明确受影响部分。

## 默认流程

1. **预检。** 查找具备 requirements.txt 依赖的 Python 3.10+ 和中文字体。pipeline prepare 接收原文、源页和字体，冻结恢复脚本、生成清单及风险。查看原页段落、扫描字和公式边界。仅命名需要时读 naming.md；重命名原文须明确批准。
2. **翻译与映射。** 读取简洁 inventory，pipeline apply 批量写入译文，merge_ids 合并完整段落。公式和标识附理由保留，仅对必要扫描文字加局部覆盖。实际查看后确认页清单，每批保存 authoring state，不手改 qc。
3. **构建。** 用冻结的 pipeline build。调整只选受影响页，同类溢出集中修复；就绪后构建完整请求范围。始终从原文及状态生成，复用指纹匹配候选。
4. **集中检查与修复。** verify 对生成状态一次渲染，同时服务审计和查看。以适当阅读尺度实际看每个需检查页，有疑问才放大，通过 review 登记观察；渲染不等于查看。原文损坏、缺页、大段漏译、乱码及主要图形遮挡需修复或明确披露受影响部分。优先处理流程缺陷，无害差异附理由保留，不改掩码追求零差异。编辑后 verify --previous-state 保留未变化页的原始证据，仅真实共享依赖或上下文变化时扩大复查。
5. **交付。** publish 检查冻结输入和证据，按相同字节发布，自动生成资源、哈希及恢复说明。普通任务做恢复一致性冒烟；独立重建和资源稳定性实验留在维护或构建资源逻辑改变时。如实报告模式、页范围、保留问题和路径；样本不可称整本译本。

## 命令与产物

完整接口见 [中文操作说明](references/practical.zh-CN.md)。每份文档独立保存 recovery/ 和 work/，仅发布验收 PDF。用户 PDF、字体及测试产物不进技能仓库。不要自动删除恢复目录，否则丢失编辑和审核证据。

低层 inplace.py、pdf_tools.py 继续支持，严格/手工细节见 inplace、state-and-qc、building 的配对参考。verify 已生成匹配证据时不重复 audit 与 render。v1/v2 保持原行为；example_build.py 仅显式旧兼容。

保留原始 144 DPI 测量（RGB 容差 16、变化比例 0.001）。阅读模式允许保留已查看右侧差异，原文损坏、字体失败、范围错误仍阻断。机器通过不代表语义认证。流程评估记录阶段耗时、工具/构建/渲染次数及返工原因，无法取得 token 则标明，不将估算当实测。
