# 技能维护与验证范围

本参考用于技能维护。历史验证记录中的文档名称和主题仅说明曾经执行的检查，不用于推定新翻译任务的领域或偏好风格。

## 仓库与安装

维护仓库为 llbk-kevin/pdf-bilingual-parallel-translate，保持私有，默认分支 main。全局入口为 <CODEX_HOME>/skills/pdf-bilingual-parallel-translate。新建的普通目录在 CC Switch 接管前留在原处，不手动迁移。

编辑前检查入口是否为链接并解析其目标，在实际目录维护。修改后确认原链接仍指向同一目标，且从入口能读到更新。尚无链接时直接维护普通目录。发现断链或独立副本分歧时，先报告，不擅自替换。

## 维护流程

明确要求修改本技能时，同步 SKILL.md 和 README.md，同时同步被修改的英文参考与 .zh-CN.md 版本，命令、格式标识和示例保持等价。普通使用读取英文入口；中文文档用于用户审阅与维护。

在合适的 Python 环境安装 requirements-dev.txt，并从实际技能目录运行：

~~~
python -m unittest discover -s tests -v
python scripts/pdf_tools.py --help
~~~

集成测试使用 ReportLab 和 pypdf 在临时目录生成小型 PDF，不依赖桌面文档或授权字体文件。运行工具需要 pypdf、pypdfium2、Pillow、fonttools，开发和可选构建范例另需 ReportLab。首版在 Windows 验证的版本为 pypdf 6.10.0、pypdfium2 5.13.0、Pillow 12.3.0、ReportLab 4.4.9。依赖文件允许兼容的小版本更新，更新后应重跑相关测试。资源清点有意使用 pypdf 6.x 的编码流内部接口，大版本升级需复核。

若安装的 skill-creator 提供校验器，则运行它，并检查 UTF-8/BOM、Markdown 链接和界面元数据。提交前检查 git diff 与跟踪文件，排除任务输入、输出、状态、渲染缓存、字体二进制和凭据。提交采用 Conventional Commits，英文 type/scope、中文说明；实质变更附多行中文正文。.gitignore 各组保留中文注释。

选定维护策略为验证后提交并推送 origin/main，不强推、不丢弃无关工作。远端有新提交时先获取并只整合已理解的变更，再验证结果。认证或推送失败时保留本地提交，如实说明剩余步骤。普通 PDF 翻译不修改或同步本仓库。

## 首版验证

18 项合成集成测试覆盖：嵌套/共享图片资源；原有重复与新增重复的区别；重复字体流；Decode 语义改变；调色板无损重压缩与数值表示；旋转/裁切；原文栅格内容破坏；链接书签丢失；表格形状与缺译；图形锚点缺失；图注位移与竖线表格提示；原文/输出/脚本/布局输入指纹变化；验收失效与覆盖缺项；渲染索引；覆盖保护；确定性的只读审计。

本地对三组原文与旧译本共 74 页进行审计：NSI826x 32 页、NSI8608 20 页、反激电源演示文稿 22 页。原文区域栅格比较全部通过，图片字节增量均为零，没有将原有重复资源误报为本次新增。警告提示了可能的表格扁平化、图注位移、中文字号偏小和链接变化。这些是诊断结果，不是对旧译本的语义准确性认证。

另行生成七页本地样例，包含 NSI826x 的双栏首页、参数表、多图页、重复公式页，NSI8608 的电路说明页，以及反激电源图形/横向表格页。七页均逐页查看，密集表格另作放大检查。样例复用原图片，没有新增位图字节，保留真实表格单元格和重复公式，使用共享字体子集；重复生成 PDF 指纹一致。原文样本 1,742,417 字节，双语样例 2,125,713 字节；图片/Form 增量为零，新增字体流编码数据 162,063 字节。样例 PDF、专用生成脚本、译文及恢复数据仅作为本地交付，不是仓库测试夹具。

## 命名、恢复与证据升级

初次迁移需求时，把“不要自动重命名原文”简化成了“保持原文件名”，丢失了识别、建议、确认及执行规则。这属于需求迁移不完整。命名参考恢复完整流程，并落实用户选定的约定：TI 英文原文与生成译本使用相同文件名，分放在不同目录。

现有 35 项合成测试在原有检查外，覆盖 TI 命名及缺失编号、标题规范化、后缀去重、原文与译本同名但路径不同、实际分配字体缺字与回退、状态驱动的完整表格单元格、溢出、外部输入保留、确定性重建、实际渲染证据、严格复用与上下文失效、仅路径迁移、固定比例非整数几何、空/显式密码、图注类型和未压缩流。测试字体由程序生成，其字形仅为夹具，不用于评价真实排版。

本地回归审计 Sensors 15 页、Moog 40 页、TDK 107 页，共 162 页；统一矩阵渲染下，全部原文区域变化像素为零。Moog 原先受页面尺寸影响的采样误差已消除，没有放宽容差。TDK 空用户密码通过正式读取器处理；103 条小字号页边文字信息与 3 条涉及脚注的小字号警告区分开，后者仍需具体审阅说明。另确认历史测评字体缺少 U+2243 和 U+2095；实际分配字体检查可以拦住这种“可提取但缺字”的情况，仍不能替代最终视觉检查。

任务迁移清单和独立重建证据留在技能仓库之外。旧版状态保留原始验收历史，重命名不伪装为版本 2 验收。本次维护不能声称重新审阅了全部旧译本。

## 等大区域与已确认页码

42 项合成测试覆盖此前行为，以及混合/非整数尺寸的等大区域构建、拒绝加宽/缩窄的旧区宽参数、输出几何与原文位置错误（保持 0.1 pt 容差）、显式原编号/物理编号、无编号封面、页码实际字体片段及失效检查。旋转/裁切样本也断言可见区域等大。可选页码字段不自动识别印刷编号。

在仓库外执行 tests/generate_layout_samples.py --out <task-dir>/samples --font <允许使用的中文TrueType字体>，按需添加 --face-index，字体与产物留在本地。三份共七页小样覆盖无编号封面及 iv/A-3 原编号、全文无编号且包含空白页，以及利用邻近页边空间和局部缩小的表格。七页及放大的表格均已实际查看；原文区像素一致，图片/Form 字节增量为零，字体与状态检查通过，重复构建字节相同。表格采用正文的 11.5 pt 时溢出，改为 8.5 pt 后放下，正文仍为 11.5 pt。这些是小型样例，不证明以后所有版面都能放下。

只读复核 Sensors（15 页）、Moog（40 页）及 TDK（107 页），原文区再次全部零像素变化。新几何检查将 Sensors/Moog 共 55 页报告为超出等大区域规则，符合当时允许加宽的排版；TDK 的 107 页均为等大区域。原文、译本及恢复状态指纹保持不变，不改写历史验收，也不把旧验收当作已符合新规则。

## 限制与后续变更

本技能不含自动翻译或统一排版引擎。翻译、原文清单覆盖和逐页查看仍由模型完成。工具不能可靠识别每一处漏句、表格扁平化、图注错位、裁切字形、ToUnicode 缺失或阅读顺序问题，启发式检查有意设为警告。有状态清单时图形提示使用明确的图注块，无清单时匹配唯一可提取图号；错误清单、重复引用和图片内图注仍可能造成遗漏或误报。字体覆盖检查验证声明的实际绘制片段及源字体，不检验最终 PDF 每个字形程序；审阅证据验证一致性，不证明审阅者理解了内容。

自动结构检查不证明无障碍结构、表单行为、图层语义、数字签名有效性或完整书签层级等价，交付说明应保留这些边界。后续根据具体失败补充测试；没有相应用户需求时，不扩展为大型排版引擎或硬编码厂商规则。
